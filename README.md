# Server Security Check Automation

KISA 「주요정보통신기반시설 기술적 취약점 분석·평가 상세 가이드」를 참고해 Linux 및 Windows Server의 일부 보안 항목을 점검하고, 가능한 경우 백업·조치·재검증까지 수행하도록 작성한 2인 팀 프로젝트입니다.

> **주의:** 학습·실습용 프로젝트입니다. 일부 스크립트는 계정, 파일 권한, 서비스, 레지스트리, ACL 등 시스템 설정을 변경할 수 있습니다. 운영 환경에서 실행하기 전에 코드를 검토하고 별도의 테스트 환경에서 검증해야 합니다. 본 저장소는 KISA의 공식 도구가 아니며 KISA와 제휴·인증 관계가 없습니다.

## 프로젝트 목표

- Linux / Windows Server 보안 점검 항목을 스크립트로 자동화
- 단순 PASS/FAIL 확인을 넘어 점검 결과를 로그와 JSON으로 남김
- 가능한 항목은 현재 설정을 백업한 뒤 사용자 확인을 거쳐 조치
- 조치 후 동일 항목을 다시 확인하여 결과를 검증
- Linux Bash와 Windows PowerShell 스크립트의 출력·처리 형식을 최대한 통일

## 구현 항목

| 구분 | 파일 | 점검 내용 |
|---|---|---|
| Linux | `U-52.sh` | 동일한 UID를 사용하는 계정 존재 여부 점검 |
| Linux | `U-57.sh` | 사용자 홈 디렉터리 소유자 및 권한 점검 |
| Linux | `U-61.sh` | FTP 서비스 활성화 여부 점검 및 조치 |
| Windows | `W-50.ps1` | 계정 암호 최대 사용 기간 정책 점검 및 조치 |
| Windows | `W-62.ps1` | SNMP 서비스 접근 제어 설정 점검 및 조치 |
| Windows | `W-71.ps1` | 이벤트 로그 관련 경로의 접근 권한 점검 및 조치 |

## 공통 처리 흐름

```text
점검(Detect)
   ↓
PASS / FAIL 판정
   ↓
조치 가능 여부 판단
   ↓
사용자 확인
   ↓
설정 백업
   ↓
조치(Remediation)
   ↓
재검증(Verification)
   ↓
로그 / JSON 결과 저장
```

항목 특성상 자동 조치가 시스템 안정성을 해칠 수 있는 경우에는 자동 수정을 수행하지 않고 수동 조치 가이드를 출력하도록 구성한 스크립트도 있습니다.

## 주요 기술

- Linux / Bash
- Windows Server / PowerShell
- `systemctl`, `ss`, `/etc/passwd`, `stat`, `awk`, `grep` 등 Linux 관리 도구

## 나의 주요 기여

이 프로젝트는 2인 팀으로 진행했습니다.

- 6개 점검 스크립트 중 **대부분의 스크립트 구현**
- Linux / Windows 스크립트의 **공통 실행 흐름과 출력 양식 통일**
- 프로젝트 보고서 공동 작성
- 최종 발표 자료(PPT) 제작
- 구현 과정에서 생성형 AI를 보조 도구로 활용하여 코드 초안 작성·수정·검토를 진행하고, 프로젝트 요구사항에 맞게 통합

모든 구현을 단독으로 수행한 프로젝트는 아니며, 팀 프로젝트의 결과물 중 공개 가능한 소스 코드와 본인의 기여 내용을 중심으로 정리했습니다.

## 실행 시 주의사항

### Linux

일부 점검 및 조치에는 시스템 파일·서비스 접근 권한이 필요할 수 있습니다. 테스트 VM에서 코드 내용을 먼저 검토한 후 실행하는 것을 권장합니다.

```bash
chmod +x linux/U-52.sh
sudo ./linux/U-52.sh
```

### Windows

일부 항목은 보안 정책, 레지스트리, ACL을 읽거나 변경하므로 관리자 권한 PowerShell이 필요할 수 있습니다.

```powershell
.\windows\W-50.ps1
```

## 한계 및 향후 개선

- 수업 프로젝트 당시의 요구사항과 테스트 환경을 기준으로 작성되어 최신 Windows/Linux 환경 전체를 보장하지 않습니다.
- 가이드 전체 항목이 아니라 6개 항목만 구현했습니다.
- 코드에 포함된 보안 위협/TTP 메타데이터는 수업 프로젝트 당시 작성된 내용으로, 본 저장소 공개 시점에 별도로 재검증하지 않았습니다.
- 운영 환경에 적용하려면 OS 버전별 예외 처리, 권한 검증, 비대화형 실행, 테스트 자동화 등의 보강이 필요합니다.
- 향후 Linux·인프라 학습 과정에서 각 스크립트를 다시 검토하고 테스트 환경에서 재검증할 예정입니다.
